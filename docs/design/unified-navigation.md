# RL Infra 统一知识导航

## 产品结构

知识库只有一个阅读工作区。目录表达技术范围，内容类型表达读者当前想查阅的材料，搜索表达筛选条件。这三个维度正交：选择章节不改变内容类型，切换类型不改变章节，搜索不会打开另一套页面。

```text
统一工作区
├── 目录：领域 → 小节 → 专题 / 框架 → 实现
├── 当前范围：面包屑、标题、内容类型及数量
│   ├── 全部（领域总览或分类结果）
│   ├── 知识
│   ├── Issues（工程案例 / 关联问答）
│   └── 框架实现
└── 同一内容区：列表 / 正文阅读 / 学习路线
```

首页直接展示十一章及各类关联内容的数量；专题范围展示三类关联材料。目录数量跟随当前内容类型与搜索条件，同一内容跨多个技术范围关联时只在各自范围内去重，章节数量不必相加等于全站数量。框架范围由具体实现与其关联知识、案例和问答组成，不能将其他框架的实现混入。

桌面与手机使用同一个目录 DOM，手机通过原生 Dialog 打开，展开状态和选中位置不复制维护。正文保留原有插图、公式、交互实验和复习功能。学习路线是辅助阅读入口，不是第四类内容。

## 路由与实现

`navigation.js` 定义唯一的可序列化状态与内容筛选：

| 字段 | 含义 |
|---|---|
| `area`, `section`, `ref` | 当前技术范围，子级由 catalog 归属规范化 |
| `framework`, `impl` | 框架章节下的关联范围 |
| `mode` | `all`、`topic`、`issues`、`implementation` |
| `q`, `kind`, `level`, `review`, `page` | 列表筛选和分页，Issue 专用筛选不会泄漏到知识或实现 |
| `topic`, `case`, `implementation`, `question`, `anchor` | 稳定正文身份与文内位置 |
| `back` | 打开结果前的本地列表 hash，经过解析和验证 |

例如 `#mode=issues&area=parallel&section=parallel-2&q=Q086` 可直接恢复张量/流水线并行下的问答搜索。打开结果时保存原列表状态，清除正文的搜索限制，读者可以看到当前范围完整的知识与框架关联。返回列表、浏览器 Back 均可恢复筛选条件；原始 `#topic=...`、`#question=Q081`、`#view=questions`、`#view=library`、`#chapter=...`、`#category=...` 继续解析。所有文章 ID 与本地复习记录 schema 保持不变。

`core.js` 保留知识索引、学习记录和教学模型；`navigation.js` 负责纯路由与选择器；`app.js` 只通过该模型渲染目录、类型标签、统一列表和阅读区。`style.css` 负责全站布局和内容列表；`reader.css` 负责正文和实验。新增专题只维护 catalog 和 learning-map，不增加按领域、类型写死的页面或路由分支。

## 验收

`test_navigation.js` 校验三类内容去重、范围规范化、框架关联边界、旧链接、筛选返回与非法路由。`browser_smoke.py` 在完整内容路由、原有交互和学习记录的回归基础上增加真实导航操作：从 TP 详情切换四种类型、在 Issues 中改变目录、搜索并打开问答、返回列表和浏览器 Back、框架范围、手机目录复用与键盘关闭。发布仍遵守 `docs/product-acceptance.md` 的完整 CI 和线上版本校验。
