# Rollout 预算：动态采样与树形探索

固定每个 Prompt 生成 G 条回答便于实现 Group Advantage，但不同任务提供训练信号的概率不同。预算分配问题是在总生成成本受限时，选择哪些任务、哪些中间状态和多少分支进行采样。

## Prompt 级筛选

对二元 Reward、独立采样、成功概率 p 的教学模型，G 条回答中至少有一对奖励不同的概率为

$$
P_{\mathrm{mixed}}=1-p^G-(1-p)^G.
$$

取 G=4，p=0.5 时为 0.875；p=0.01 时约 0.0394。如果只接受混合奖励组，同样收集 100 个有效组，前一种任务平均需要约 114 组尝试，后一种约 2538 组（独立且通过率稳定的理想估算）。实际回答相关、失败与长度差异会改变成本。

DAPO 的 Dynamic Sampling 是此类方法的代表：通过筛选全同奖励组并补充采样，让训练 Batch 包含有相对信号的组。它会改变进入 Learner 的任务分布。若原始任务分布为 d(x)，接受概率为 a(x)，接受后的分布与 d(x)a(x) 成正比；除非接受概率恒定或另有纠正，二者并不相同。

## 从完整回答到状态分叉

树形采样将共享的 Prompt/Action Prefix 作为中间状态，选择某些节点继续生成多个后缀。例如三条 1000 Token 轨迹共享前 600 Token，逻辑总长度为 3000；若只计算一次共同前缀，唯一前缀与后缀 Token 数为 600+3×400=1800。这个数字表示结构上的复用机会，实际 GPU 成本需计入 KV 驻留、批处理和分支调度。

选择高熵、高 Value 不确定性或有学习价值的节点，是采样策略；保持环境快照、KV 与身份一致，是运行时机制。共享 Prefix 中的动作只发生过一次还是按叶子轨迹重复计入 Loss，取决于目标如何定义。盲目复制父路径会把共享动作按叶子数加权；树形信用分配必须显式处理父子关系及样本权重。

## 预算与观测

记录任务 ID、分支父节点、行为版本、选择/接受概率（若估计器需要）、有效 Action Mask、Reward、生成 Token 和废弃成本。对固定 G、任务级动态采样和树形采样分别固定总 GPU-hour 或总生成预算，比较有效梯度样本量与独立任务质量，而不是只比较通过率。

推理时搜索直接选择当前答案；这里的分支用于采集训练数据。历史 Replay 还引入分布和版本差异，详见 [Importance Sampling](importance-sampling.md) 与 [异步 Rollout](../async/async-rollout.md)。
