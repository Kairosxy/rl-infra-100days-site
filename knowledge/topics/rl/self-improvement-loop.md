# Self-training、Self-play 与自我改进循环

训练数据可以来自模型本身。生成候选、获得反馈、筛选数据并更新模型，构成一次自我改进循环。不同方法的区别在于谁提出任务、谁验证结果、反馈来自哪个分布，以及训练更新改变了什么。

## 数据、反馈与课程

| 分支 | 改变的对象 |
|---|---|
| Self-training / Rejection Sampling | 从生成结果中筛选监督数据，再训练模型。 |
| Self-rewarding | 让模型承担评价者职责，反馈或偏好可随迭代变化。 |
| Self-play | 与自己或历史版本交互，通过对抗或合作形成学习信号。 |
| Automatic Curriculum | 根据当前能力生成或选择有学习价值的任务。 |
| RSI | 更广的递归改进目标，涉及持续改进能力乃至改进机制本身，需要额外证据。 |

Self-Rewarding Language Models（2024）研究由语言模型给自身提供偏好评价，并迭代执行 DPO。Absolute Zero（2025）让模型参与提出和解决可验证代码任务，由执行器约束任务及答案。两个例子都减少了特定类型的外部数据依赖，但验证器、初始模型、训练目标和计算预算仍是重要条件。它们的实验范围不能直接推广为通用 RSI。

## 自评误差如何累积

假设生成 1000 条候选，其中真正正确的有 400 条。Verifier 对正确答案的接受率为 0.9，对错误答案的误接受率为 0.2。期望保留正确样本 360 条、错误样本 120 条，筛选后的正确率为 75%。若下一轮自评变宽松，错误误接受率升至 0.5，保留的错误样本变为 300 条，筛选后的正确率约 54.5%。数据量增大并不保证监督质量提高。

以上是固定候选分布的计算例子。真实自我改进中，模型和数据分布会同时改变；历史任务难度也可能变化。只看当前 Verifier 的 reward 曲线容易把评价标准变化误认为能力增长。

## 跨迭代证据

保留 generator、judge、task proposer 和 learner 的版本身份，记录每轮任务分布、正确/错误接受率、独立留出评测与计算消耗。比较固定外部反馈、冻结历史评估器和随模型更新的评估器；在 Self-play 中同时比较固定对手与历史对手池，防止循环策略或相对分数漂移掩盖退化。

对于任务生成型循环，定义去重、可解性、验证器正确性与难度约束。模型会提出更难的任务并不自动意味着训练有用；应当检查新任务是否使固定独立评测的能力提高，以及单位计算得到多少增量。
