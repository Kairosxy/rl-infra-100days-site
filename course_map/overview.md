# 课程应该怎样教，学生才能真正学会

> **历史教学设计（归档）**：目前网站采用 [Topic / Case / Implementation](../knowledge/README.md) 的知识库结构，本文件只保留早期设计记录，不作为当前发布规则。


本项目从学习者的一个真实疑问开始，而不是从“今天需要介绍十个术语”开始。目标不是把 RL、SGLang、Megatron、Ray 的文档分别压缩成小卡片，而是能独立判断一次更新对不对、瓶颈在哪里、架构改动有没有偷偷改掉算法的目标。

## 学生拿到一节新课，看到什么才有意义？

讲义第一屏直接放一个能判断对错的具体问题。例如：一个样本的 Reward=1，模型到底更新了哪个参数？一个 Training Loss=0，为什么梯度还可能非零？当最后一步是截断而不是终止时，Value 该不该 Bootstrap？

先让学生看到输入、答案可能出现的两种结果，再解释为什么只有其中一种符合定义。推导符号只在需要时引入；**讲到变量就注明它代表的概率、张量还是状态，不让学生先背抽象名词。**

一个课程合格与否，只看能不能给学生以下证据：

1. **能复算**：有具体数字、推导过程、明确的结果与适用前提；不靠相信作者。
2. **能辨错**：有一个会使错误实现暴露的反例；解释为什么 Shape、Loss 或均值“看着正常”仍可能错。
3. **能对应代码**：从数学符号能找到 Tensor/数据字段、shape、dtype、生命周期和更新时机；不知道具体框架路径就不要编造。
4. **能看出代价**：属于算法课，估算采样方差与样本预算；属于系统课，估算 FLOPs、字节、显存/通信/等待；没有实测时写清理论边界。
5. **能继续问下去**：不是“恭喜掌握”，而是学生可以自己改变一个条件，预测哪些值会变化。

简单名词解释不占整篇。真正需要 30–60 分钟推导的内容不压缩为“公式 + 三句概念”。**篇幅由推理难度决定，不能用每天固定五个小标题来控制。**

## 导师讲解分层，但不把分层当作页面格式

Tutor 可在内部把一节内容分成：直觉与锚点 → 不变量与前提 → 机制/算法 → Tensor/源码 → 失败与 Debug。学生看到的仍应是自然连贯的讲义，而不是五个“Layer”模板标题。没有前提就补一个两分钟例子，已经理解的基础术语立即略过；对用户提问“为什么/有什么反例/具体代码”，直接往后两层深入。

旧版“非完成不得解锁”和机械评分表已取消。练习可直接查看答案，可跳过，重复错误记录应基于实际回答证据而非助手臆测。用户的个人笔记、错误和作答默认保存在本地，不公开上传。

## 交互不是表演动画

交互组件只有能够引出**反事实**才值得开发。页面先给条件和预测，再允许学生修改一项参数，最后标出变更后的数值/曲线/状态。比如把 $p=0.5$ 改为 0.01 会导致多少次零 Reward；把 Mask 中一个 Padding Token 从 0 变成 1 会对梯度有什么影响；把 PPO Ratio 拉到 Clip 平台后还能不能继续产生同一样本的梯度。

同一课允许完全没有交互。实际实验应按「输入 → 可以预测的输出 → 一个有意破坏前提的开关 → 哪个 Assertion/数值变化」编写需求。图像只在结构/时间/位置难靠文字表达时增加；优先可编辑 SVG，暖白背景、深灰文字、克制绿/橘，数字、Token 位置和状态线准确优先于视觉装饰。

## 技术文献的使用方式

经典工作用来建立机制：Policy Gradient / REINFORCE、GAE、PPO、FlashAttention、PagedAttention。较新的 LLM RL 方案，包括 GRPO、DAPO、GSPO、异步训练及 OPD，都必须沿着“原来什么失效 → 论文做了什么 → 哪些证据支持 → 还有哪些边界”分析。**框架与论文不替代推导**，论文声称的吞吐量也不等于本项目的测量结果。

资料库与日程在 [day_schedule.md](day_schedule.md)，由同一个可复算的参考案例衔接 GPU/多卡/Serving/Agent/异步的路线写在 [system_roadmap.md](system_roadmap.md)。
